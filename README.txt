 เฟส 5 (20260920k) — ปฏิทิน/คำนวณ/สัญญา เข้า Design System
===================================================================
ปัญหาเดิม: แอปใช้คลาสสีของ Tailwind (slate/stone/cyan/...) 371 จุด 60 แบบ
           ทำให้หน้าเหล่านี้ไม่เข้าชุดสีใหม่ และโหมดมืดอ่านไม่ออก

วิธีแก้: ผูก utility สีเก่าเข้ากับ token ที่ CSS ที่เดียว แทนการไล่แก้ JSX ทีละจุด
  - ตัวหนังสือ slate/stone/gray-300..900  -> --c-text-3 / --c-text-2 / --c-text
  - สีเน้นเดิม cyan/sky/blue              -> --c-primary (+ soft/border)
  - สถานะ red / amber / green            -> --c-danger / --c-warning / --c-success
  - พื้น bg-white / stone-50 / stone-100  -> --c-card / --c-card-alt
  - gradient cyan-800 -> cyan-950         -> ไล่สี primary -> primary-deep
  - rounded-2xl / rounded-xl / shadow-sm  -> --r-card / --r-md / --sh-card

แก้สี hardcode ที่เหลือในปฏิทิน (เลขวันมองไม่เห็นในโหมดมืด), หัวชื่อวัน,
ปุ่มเรียงลำดับ และเส้นขอบแถวที่จ่ายแล้ว

⚠ บั๊กที่เจอระหว่างทาง: มี CSS variable หลุดเข้าไปในโค้ดวาดรูป 18 จุด
   (generateDebtorImage / chitReportImage / chitMemberImage / รูปตารางผ่อน)
   canvas อ่าน var() ไม่ได้ ตัวหนังสือในรูปที่ส่งเข้าไลน์จะหาย — คืนค่า hex แล้ว

                 + วัด contrast ตัวหนังสือบนการ์ด สว่าง/มืด (>=7:1 และ >=4.5:1)
  test-nohardcode  กันสี hardcode กลับเข้ามาในโค้ด UI (ยกเว้นบล็อก canvas

ที่มา: Tk ไม่ใช่เจ้ามือ อยากใส่ดอกที่คาดไว้ "แยกรายงวด" (เช่น 1,200 / 1,800 / 3,300)

--- สูตร (ใช้ chitProject ตัวเดิม ไม่สร้างสูตรใหม่) ---
  ถ้าเราเปียงวด k:  สุทธิ = ดอกของมือก่อนหน้ารวมกัน − (งวดที่เหลือหลังเปีย × ดอกของเรา)
  พิสูจน์: เทียบกับการวนจ่ายจริงทีละงวด สุ่ม 300 วง × 19 งวด ต่างกัน 0 บาท

    ตัวอย่างดอกของ Tk: มือ 10 = +1,300 แต่มือ 11 (ดอก 2,800) = −9,600 แล้วมือ 12 = +5,600
  ข้อเท็จจริง: มือสุดท้ายกำไรมากสุด "เสมอ" (สุ่ม 300 แผนยืนยัน)

    · ไม่ขาดทุนแน่ตั้งแต่ (ทุกงวดหลังจากนั้นไม่ติดลบเลย)

  · แผนบันทึกอัตโนมัติ ปิด-เปิด/รีเฟรชแล้วยังอยู่ (เก็บใน g.plan — ฟิลด์เสริม ข้อมูลเก่าไม่กระทบ)
